# RunawayScout — Product Design & Implementation Blueprint

An intelligent, multi-stage agentic web scraping and research assistant that turns ambiguous user inputs into comprehensive, fact-grounded reports.

---

## 🚀 Stage-by-Stage Architecture

### 📋 Stage 1: Input Parsing, Parameterization & Clarification
This phase aligns the research scope and clarifies assumptions with the user before executing any queries.

*   **Prompt Analysis & Rephrasing:** An LLM rephrases and parses raw user queries to generate optimal search terms.
*   **Time & Depth Budgeting:**
    *   **Research Duration:** User selects time budgets (e.g., `1 hour`, `2 hours`, `1 day`, `1 week`, etc.).
    *   **Research Depth:** User sets depth categories (e.g., `Surface Level`, `Medium Depth`, `Deep Research`).
*   **Active Clarification Questions:** The parser analyzes the rephrased query and asks the user 3–5 targeted questions to narrow the scope.
    *   *UI Requirement:* Includes an open-text input box next to questions for user custom additions.
*   **Assumptions Verification:** The model lists all of its inferred assumptions about the topic. The system loops and cross-questions the user until all ambiguities are resolved.

---

### 🔍 Stage 2: Smart Source Discovery & Quality Prioritization
The system dynamically finds and classifies web sources, ranking them by authority to ensure high-quality findings.

1.  **Tier 1 (Highest Priority):** Professional consultancy reports, private research databases, data collection firms' blogs/reports, and analyst publications (e.g., McKinsey, BCG, Bain, PwC, Deloitte, Grand View Research).
2.  **Tier 2 (Secondary Priority):** Government/official portals (`.gov`, `.org`), online libraries, and authoritative paywalled/login-walled content (e.g., SEC Filings, IMF, World Bank, OECD).
3.  **Tier 3 (Third Priority):** General web resources, data aggregators, news sites, and reference websites.
4.  **Tier 4 (Community/Social Grounding):** Community forums (e.g., Reddit, Quora, Brainly) where real-world experiences, user reviews, and personal stories are shared.

---

### 📄 Stage 3: Targeted Scraping, Synthesis & Rich Document Generation
The scraping phase is surgical rather than exhaustive, saving time and API budget.

*   **Surgical Scraping:** Rather than broad crawling, it scrapes specific pages selected based on the user's depth and duration parameters.
*   **Analysis & Structuring:** Scraped data is structured by an LLM and formatted according to user preferences (using report templates where applicable).
*   **Rich Media Generation:** If the user requests an *analytical report*, the AI synthesizes findings and embeds relevant charts, graphs, and images (either extracted from scraped sites or generated by the agent itself).

---

## 📂 Output Folder Structure

All research sessions automatically create a dedicated, time-stamped directory inside the `output/` folder named based on the topic. No data is kept hidden; everything collected is saved for the user.

```
output/
 └── 📁 [AI_Generated_Topic_Name_Timestamp]/
      ├── 📄 01_search_parameters.md        # The final prompt, assumptions, and user constraints
      ├── 📄 02_raw_scraped_data.txt        # Live-updated file with raw text, timestamps, and URLs
      ├── 📄 03_final_analysis_output.md    # The synthesized, formatted final report
      └── 📁 media/                         # Downloaded or AI-generated graphs and images
```

### 📄 File Contents & Heuristics:
1.  **`01_search_parameters.md`**: Logs the initial query, rephrased search terms, parameters (time & depth budget), assumptions list, and user answers to clarification questions.
2.  **`02_raw_scraped_data.txt`**: Live-appends raw page content, source URLs, and timestamps **during scraping**. If a crash happens, this file guarantees no gathered data is lost.
3.  **`03_final_analysis_output.md`**: The clean, polished research report synthesized by the LLM, containing structured tables, headers, and clickable footnotes back to `02_raw_scraped_data.txt`.
4.  **`media/`**: Houses relevant diagrams, downloaded illustrations, and generated charts referencing data in the report.

## 🛠️ API & Infrastructure Architecture

### 🔄 Multi-API Fail-Safe Rotation
*   **API Configuration:** UI has a button letting users add additional keys/APIs.
*   **Quota & Rate-Limiting Resilience:** API boundaries (especially lower limits like free-tier Gemini 2.5 Flash) must be respected. 
*   **Batching & Chunking:** Queries are structured so that any single API call doesn't exceed its rate bounds.
*   **Robust Error Logging:** All failures are logged gracefully without halting the application. Multiple keys/APIs are rotated dynamically to execute sub-tasks efficiently.

---

## ⚠️ Current Issues & Improvements

- [ ] **Scraping Quality & Strategy:** The scraping engine needs to use more efficient, modern traversal and content-extraction methods.
- [ ] **Parsing Latency:** Stage 1 input parsing is slow. It needs to be optimized for faster response loops.
- [ ] **Clarification Loop Extension:** Users should be able to ask follow-up questions during the clarification step to refine the query further.
- [ ] **UI/UX Modernization:** The interface is currently functional but needs visual and user-experience polish to make it premium and intuitive.
- [ ] **Graceful Failure Outputs:** *Crucial constraint:* Sometimes the scraper spends a long time processing but returns nothing to the file if a crash occurs. The system must persistently dump scraped data to a raw log file in real-time, ensuring that **even on program failure, the collected raw data and source URLs are fully preserved and delivered to the user.**
